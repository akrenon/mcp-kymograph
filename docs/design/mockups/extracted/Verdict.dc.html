A recorded cap is complete

One message records at most 20 findings. Past that, findings_capped names every statement and signal it cut, with the true numbers. What was cut, and why, is known — the run is complete. If that event is lost, or its numbers do not add up, the run is incomplete again (cap_unaccounted).

The same idea for pagination: a listing cut at the driver’s page limit is capped, not complete — a truncated listing must not read as a full one. A comparison marks a gone finding whose pair the later run cut (cap_hint).
